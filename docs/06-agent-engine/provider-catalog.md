# Provider catalog

PlanMo Phase 3 task 23 deliverable, built from the provider-selection checklist in
`docs/PLAN-ai-setup-and-codebase-suggestions.md` (the "OpenCode / Models.dev provider catalog" section).
It turns those 228 checked candidate rows into one catalog.

**This is a discovery catalog, not a support matrix.** A row here is never proof that PlanMo can call the
provider, that its API is compatible with a declared wire format, or that third-party OAuth is permitted.
PlanMo's actual runtime surface is the eight presets in `packages/ai/src/providers.ts`; only the rows whose
`Status` is `runtime-supported` name an id that is already one of them.

## How to read this table

| Column | Meaning |
| --- | --- |
| Provider id | The catalog id from the checklist, preserved verbatim. |
| Name | The provider's display name from the source snapshot. |
| Official API docs | The provider's own documentation URL, as declared by the source snapshot. |
| Protocol | The request/response shape the provider's client SDK implies (`(sdk-hint)`), or `(doc-verified)` when the provider's own documentation was read. A hint is not a verified wire-protocol claim. |
| Auth methods | Declared credential environment variable names, and the auth method where one was verified. `unverified` where the provider's own auth documentation was not read. |
| Model-list support | `yes — GET <url> (doc-verified)` only when a documented list endpoint was read; otherwise `unverified`. Never inferred from the endpoint column. |
| Endpoint / region | The API base URL declared by the source snapshot (placeholders kept as-is), with a region note when the id or URL declares one. |
| Retention & pricing | A link only when that page was actually fetched; otherwise `unverified`. PlanMo makes no retention promise. |
| Status | `runtime-supported` (already a PlanMo preset), `catalog-only` (default; no promise), or `not-supported` (no usable hosted inference API). |

## What this catalog does not claim

- It does not claim PlanMo support for any `catalog-only` row, and it does not authorize any OAuth or
  account-plan login. OAuth stays provider-specific and gated (Phase 4).
- It does not treat a provider id, a coding-agent integration, a model id, and a subscription plan as
  interchangeable. `@planmo/agent-bridge` declares coding-agent install targets; those are not model
  inference providers and are not listed here.
- It does not carry credential values. Only environment-variable names are recorded.
- It does not report retention policies on any provider's behalf.
